# Repository conventions

This repository publishes **mORMot2 Daily**, a static site that explains what changed
in the public [synopse/mORMot2](https://github.com/synopse/mORMot2) repository, one
edition per day.

## What an agent is asked to do here

Only one thing: read `data/raw/<edition>.json` and write
`data/analysis/<edition>.json`. The full task is in `PROMPT.md`, which is what the
scheduled workflow sends as the session prompt.

## Rules

- **Write one file per task**: `data/analysis/<edition>.json`. Nothing else.
- **Reader-facing text is multilingual**: `en` is required, `fr`/`zh`/`ru` are
  optional; see the Languages section of `PROMPT.md`. Identifiers — unit, type
  and method names — stay verbatim in every language.
- **Never edit** `data/raw/**`, `data/state.json`, `scripts/**`, `schema/**`,
  `site/**` or `.github/**` unless the task explicitly asks for it.
- **Never write HTML.** The site is generated by `scripts/build_site.py` from the
  analysis JSON. Layout is not your concern; accuracy is.
- **Validate before opening the pull request**:
  `python scripts/validate_analysis.py --edition <edition>` must print `OK`.
  Install its dependency first if needed: `pip install jsonschema`.
- **One pull request per edition.** If you are asked to fix a review, amend the
  branch that is already open instead of starting a new one.
- Commit message: `analysis: mORMot2 Daily edition <edition>`.

## Layout

```
data/raw/<date>.json        upstream commits + diffs (input, machine-written)
data/analysis/<date>.json   the review (output, what you write)
data/state.json             fetch bookkeeping — never edit by hand
schema/analysis.schema.json the contract the analysis must satisfy
scripts/                    fetch, Jules client, validator, site generator
site/assets/                CSS and JS copied verbatim into the built site
PROMPT.md                   the editorial brief sent to the reviewer
```

## Local checks

```bash
pip install -r requirements.txt
python scripts/validate_analysis.py --all      # contract
python scripts/build_site.py --out /tmp/_site  # generator
```

Both run in CI on every pull request (`.github/workflows/validate.yml`).
